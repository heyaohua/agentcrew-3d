# 观察大屏工作区与休息区

状态：用户于 2026-11-05 确认实施。待处理人物采用休息区金色提醒。此文档不代表已实现或已验收。

## 目标

保留“AgentCrew 3D”名称和只读 Hook 观察方式，通过人物位置、动作与电脑屏幕，让用户直观看到哪些 Agent 正在工作、哪些正在休息。3D 与 2D 保持相同状态含义。

## 方案

采用现有场景内的相邻双区域：工作区放电脑工位，休息区放茶桌、座椅和游戏设施。复用现有角色与导航，新增喝茶、玩游戏表现和屏幕状态联动。

仅摆放两类家具不能体现状态；重建渲染器会增加无关改动。因此建议在现有渲染器中实现状态驱动的双区活动，用户已确认。

## 行为约定

- 正在工作：走向分配的工位，坐到电脑前，屏幕亮起并显示工作动效。
- 就绪、回合结束或中断：屏幕熄灭，人物离开工位，到休息区喝茶或玩游戏；保留各自原始状态文字，不将回合结束等同任务验收。
- 再次开始工作：立即停止休闲动作，返回工位；避免人物瞬移。
- 等待用户处理：拟安排在休息区，保留金色提示及待处理计数，与普通休闲人物区分。用户已确认。
- 错误：保留醒目的错误标记，不能只显示成普通休闲。
- 状态过期或服务断开：保留最后已知位置，暂停工作动效、调暗屏幕并显示状态待更新，不凭超时推断任务完成或确定空闲。
- 会话已关闭：人物离场，历史记录仍可查看。

工位按会话分配，休息位置从固定共享家具的空坐点中分配，避免多人挤占同一坐点。休闲动作属于可视化表达，不代表终端实际在运行游戏或喝茶相关任务。

## 边界

不新增终端控制能力，不改现有 Hook、不要求重启 Agent，不采集提示词或工具输出，不恢复厨房、健身房等无关区域。不改变普通运行时办公室的行为。

## 验证

分别验证工作到休息、休息到工作、等待、错误、过期和关闭；检查屏幕仅与工作表现联动、走位可达、无座位重叠。用隔离事件验证转场，与真实 Hook 接收验证分开记录。最后在可见浏览器检查 3D 和 2D 实际画面、交互及脚本错误，独立核查状态没有被动画篡改。

## 用户纠正（2026-11-05）

用户明确指出休息区不应再摆电脑。最终休息区采用沙发、低茶几、茶杯和实体桌游（棋盘/纸牌），移除电脑、电子屏和街机；工作电脑仅保留在工作区。


## 共享生活空间纠正（2026-11-05）

用户进一步明确：工作区维持整齐的一人一机；休息区应按真实茶水间/客厅设计，不能按人数复制沙发茶几。固定共享的大L型沙发、共用茶几、沿墙茶水台、窗边长沙发与共享桌游桌决定坐点和朝向。空闲人物占用空坐点，回去工作后释放；冻结人物保留占位。休息家具数量不随会话数量变化，超出座位容量时在通道候座，不重叠、不凭空增添私人休息套件。沙发上的人物可以自然喝茶或休息，桌游只在桌游位置表现，不强制每18秒轮换成统一活动。
